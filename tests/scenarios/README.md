# 手动验收场景

自动测试（`tests/test_cross_agent.py`）只覆盖脚本本身。下面这些要用真实的 Agent 跑，会消耗额度。

**准备：** 新建一个空目录并 `git init`，然后运行 `./install.sh <目录>`。

| # | 怎么做 | 通过标准 |
|---|---|---|
| T1 | 在 Claude Code 里说「我要做一个 XX」 | 自动生成 SPEC.md 和 STATE.md，没有生成其他文档；提问 ≤ 5 个，而且都是会改变方案的问题 |
| T2 | 接着让 Claude Code 做完 1～2 项任务，然后打开 Codex 说「继续这个项目」 | Codex 开工前能说出目标、下一步和关键决定；你不用补充解释 |
| T3 | 让 Codex 做到一半直接关掉（不存档），留下没提交的改动；换 Claude Code 说「继续这个项目」 | 能说出「第 N 项做了一半，差什么」；不重做已完成的项 |
| T4 | 手动把 STATE 里某个没做完的项改成 `[x]`，再换 Agent | 发现和代码对不上，以代码为准修正 STATE |
| T5 | 聊天里先后讨论方案 A、B、C，最后选 C，然后存档 | STATE 里只写「用 C，原因…」，最多附一句为什么不用 A、B |
| T6 | 删掉 STATE.md 里的进度，只保留模板，再换 Agent | 走 recover，从聊天记录补回关键决定和进度，并说明补了什么 |
| T7 | 连续接力 10 次 | STATE 始终 ≤ 80 行，SPEC 基本没变长 |
| T8 | Claude Code ⇄ Codex 双向各测一次，OpenCode 测一次 | 都能按规则开工对账 |
| T9 | 界面项目里放一份 DESIGN.md，中途换 Agent 改页面 | 新页面沿用原来的配色、间距和组件 |

每次测试记录：用了哪两个 Agent、你补充解释了几句、哪一步出了问题。
